Prowadzący buduje projekt na ekranie, a cała grupa wykonuje te same kroki. Po każdym etapie zatrzymujemy się, przewidujemy rezultat i sprawdzamy go w przeglądarce.

01

ORGANIZACJA

Jak pracujemy podczas tych zajęć

To nie jest zadanie wykonywane od razu samodzielnie. Nie kopiuj całego materiału naprzód. Obserwuj ekran prowadzącego, wpisuj kod razem z nim i uruchamiaj stronę w tych samych momentach.

  1. Najpierw przewidujemy. Zanim odświeżymy stronę, próbujemy określić, co się zmieni.
  2. Potem uruchamiamy. Po małym fragmencie zapisujemy plik i sprawdzamy rezultat.
  3. Porównujemy. Jeżeli wynik jest inny niż na ekranie, zatrzymujemy się i wspólnie szukamy różnicy.
  4. Eksperymentujemy. Po działającym kroku zmieniamy jedną wartość i obserwujemy konsekwencję.
  5. Wracamy do wersji bazowej. Dopiero wtedy przechodzimy do następnego etapu.
Zasada prowadzącego

Nie wklejaj gotowego projektu. Pisz kod w tempie grupy, nazywaj znaki, wcięcia i plik, w którym pracujesz. Po każdym większym fragmencie pokaż jednocześnie edytor, stronę i narzędzia deweloperskie.

01

SZKIELET

Zacznij od pełnego dokumentu

Wpisz poniższy kod do index.html. Prowadzący objaśnia każdą linię przed jej wpisaniem.

<!doctype html>
<html lang="pl">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Wizytówka programisty</title>
</head>
<body>
  <h1>Moja wizytówka</h1>
</body>
</html>

Zapisz plik i odśwież stronę. Porównaj tekst widoczny w karcie przeglądarki z tekstem wyświetlanym w dokumencie.

DevTools — sprawdź

W zakładce Elements rozwiń html, head i body. Odszukaj lang="pl", meta charset, title oraz h1. Zwróć uwagę, że DevTools pokazuje drzewo DOM utworzone przez przeglądarkę.

05

45–70 MIN

CSS — nadaj stronie wygląd

01

POŁĄCZENIE

Dołącz arkusz stylów

Wewnątrz head, pod elementem title, dodaj:

<link rel="stylesheet" href="styles.css">

Dodaj ten sam element link w sekcji head wszystkich trzech dokumentów HTML. Jeden arkusz stylów może obsługiwać cały serwis.

W styles.css wpisz testową regułę, zapisz oba pliki i odśwież stronę:

body {
  background: tomato;
}

Jeżeli tło się zmieniło, połączenie działa. Usuń testową regułę — jej zadaniem było wyłącznie potwierdzenie poprawnej ścieżki.

DevTools — sprawdź

W Network odśwież każdą podstronę i znajdź żądanie styles.css. Powinno zakończyć się bez błędu 404. W Elements → Styles wybierz body i sprawdź, czy reguła background: tomato pochodzi z pliku styles.css.

PYTANIE DO GRUPY

Co oznaczają trzy części reguły: selektor body, właściwość background i wartość tomato?

02

BAZA

Ustal kolory, typografię i model pudełkowy

Wpisuj reguły blok po bloku. Po każdym bloku zapisz plik i zobacz zmianę.

/* Wszystkie elementy wliczają padding i border do swojej szerokości. */
* {
  box-sizing: border-box;
}

body {
  margin: 0; /* Usuwa domyślny margines przeglądarki. */
  min-height: 100vh; /* Zapewnia wysokość co najmniej całego okna. */
  font-family: Arial, sans-serif; /* Ustawia krój pisma z zapasem. */
  color: #e8fff5; /* Ustawia podstawowy kolor tekstu. */
  background: #101815; /* Ustawia tło całej strony. */
}

header,
footer {
  padding: 16px 24px; /* Dodaje przestrzeń wewnątrz nagłówka i stopki. */
}

main {
  min-height: 75vh; /* Rezerwuje większość wysokości okna na treść. */
  display: grid; /* Włącza układ Grid. */
  place-items: center; /* Wyśrodkowuje zawartość w obu osiach. */
  padding: 24px; /* Odsuwa treść od krawędzi. */
}
DevTools — sprawdź

Wybierz body i odnajdź zakładkę Computed oraz diagram modelu pudełkowego. Zmień tymczasowo margin lub padding w panelu Styles. Wyłączaj reguły polami wyboru i obserwuj, która z nich odpowiada za daną zmianę. Modyfikacje w DevTools nie zapisują się w pliku.

03

KOMPONENT

Ostyluj kartę i jej elementy

/* Główny kontener wizytówki. */
.card {
  width: min(100%, 560px); /* Szerokość elastyczna, maksymalnie 560 px. */
  padding: 32px; /* Wewnętrzny odstęp od krawędzi karty. */
  border: 1px solid #4cffb0; /* Zielone obramowanie karty. */
  border-radius: 16px; /* Zaokrągla narożniki. */
  background: #17231f; /* Odróżnia kartę od tła strony. */
}

/* Mała etykieta nad głównym nagłówkiem. */
.eyebrow {
  color: #4cffb0; /* Kolor akcentu. */
  font-size: 12px; /* Zmniejsza tekst etykiety. */
  letter-spacing: 0.12em; /* Zwiększa odstępy między literami. */
}

/* Główny nagłówek strony. */
h1 {
  margin-top: 8px; /* Zmniejsza odstęp nad nagłówkiem. */
  font-size: 40px; /* Powiększa najważniejszy tekst. */
}

/* Elementy każdej listy. */
li {
  margin-block: 8px; /* Dodaje pionowy odstęp między elementami. */
}

/* Wspólne ustawienia linku i przycisku. */
a,
button {
  display: inline-block; /* Pozwala stosować marginesy jak dla pudełka. */
  margin-top: 16px; /* Oddziela kontrolki od treści powyżej. */
}

/* Wygląd przycisku interakcji. */
button {
  margin-left: 8px; /* Oddziela przycisk od linku. */
  padding: 10px 14px; /* Powiększa obszar przycisku. */
  border: 0; /* Usuwa domyślne obramowanie. */
  border-radius: 6px; /* Zaokrągla narożniki przycisku. */
  font: inherit; /* Dziedziczy krój pisma ze strony. */
  color: #101815; /* Ustawia ciemny tekst. */
  background: #4cffb0; /* Ustawia kontrastowe tło. */
  cursor: pointer; /* Pokazuje kursor dłoni nad przyciskiem. */
}

Porównaj selektory typu (h1, button) z selektorami klas (.card, .eyebrow). Klasa może wystąpić na wielu elementach; identyfikator powinien wskazywać unikalny element.

DevTools — sprawdź

Wybierz element z klasą card. W panelu Styles znajdź regułę .card, a w Computed odczytaj końcową szerokość, padding i kolor tła. Zmień szerokość okna i obserwuj działanie width: min(100%, 560px).

MINI-EKSPERYMENT

Zmień kolejno padding, border-radius i kolor akcentu. Po każdej zmianie odpowiedz, która część pudełka lub interfejsu została zmodyfikowana.

06

70–90 MIN

JavaScript — zareaguj na kliknięcie

01

KONSOLA

Najpierw potwierdź uruchomienie skryptu

Przed zamknięciem body w index.html dodaj:

<script src="script.js"></script>

W script.js wpisz:

console.log("Skrypt działa");

Zapisz pliki, odśwież stronę i odczytaj komunikat w zakładce Console. Komunikat nie pojawia się w treści strony, ponieważ konsola jest narzędziem dla programisty.

DevTools — sprawdź

W Network znajdź wczytany script.js, a w Sources otwórz jego treść. Konsola powinna pokazać jeden komunikat po każdym odświeżeniu. Filtr Errors nie powinien zawierać wpisów.

02

DOM + ZDARZENIE

Znajdź elementy i obsłuż kliknięcie

Zastąp testowy kod w script.js następującym programem:

const factButton = document.querySelector("#fact-button");
const bio = document.querySelector("#bio");

factButton.addEventListener("click", function () {
  bio.textContent = "Ta treść została zmieniona przez JavaScript.";
  factButton.textContent = "Gotowe!";
});

Nie klikaj od razu. Najpierw wspólnie przeczytajcie program od góry i przewidźcie:

  • który element trafi do zmiennej factButton;
  • kiedy wykona się funkcja przekazana do addEventListener;
  • które dwa teksty zmienią się po kliknięciu;
  • co wydarzy się po drugim kliknięciu.

Dopiero potem odśwież stronę, kliknij przycisk i porównaj rezultat z przewidywaniem.

DevTools — sprawdź

W Elements obserwuj elementy #bio i #fact-button podczas kliknięcia — zmienione węzły zostaną na chwilę podświetlone. Następnie w konsoli wpisz bio oraz factButton i sprawdź, jakie elementy przechowują zmienne.

    ✓
  • Po kliknięciu zmienia się opis i etykieta przycisku.
  • W konsoli nie ma czerwonych błędów.
03

DEBUGOWANIE

Wywołaj kontrolowany błąd

  1. W selektorze zmień chwilowo #fact-button na #fact-buton.
  2. Odśwież stronę i kliknij przycisk.
  3. Odczytaj pierwszy czerwony komunikat oraz numer linii w konsoli.
  4. Sprawdź w konsoli wartość wyrażenia document.querySelector("#fact-buton").
  5. Przywróć poprawny identyfikator i upewnij się, że interakcja znów działa.
DevTools — sprawdź

Kliknij numer linii przy błędzie, aby przejść do pliku w Sources. Dodaj breakpoint w pierwszej linii funkcji obsługującej kliknięcie, kliknij przycisk i obejrzyj wartości zmiennych w panelu Scope. Wznów wykonanie przyciskiem Resume.

Błąd to informacja

null oznacza tutaj, że selektor nie znalazł elementu. Zacznij diagnozę od pierwszego błędu, numeru linii i sprawdzenia nazw po obu stronach połączenia HTML–JavaScript.

07

MAPA POŁĄCZEŃ

Jak pliki odnajdują siebie nawzajem

PołączeniePunkt zaczepieniaCo zepsuje połączenie?
HTML → CSS<link href="styles.css">Zła nazwa pliku, ścieżka lub brak rel="stylesheet".
CSS → HTML.card pasuje do class="card"Literówka, brak kropki przy klasie lub inna nazwa.

W Network włącz filtr All i odśwież stronę. W jednym miejscu zobaczysz dokument HTML, arkusz CSS i skrypt JavaScript. Kliknij każdy zasób i porównaj jego typ, adres oraz odpowiedź.

WSKAZÓWKI

Jeśli utkniesz

Wskazówka do wariantu A

Najpierw dodaj poprawny element section w article. Dopiero potem dodaj klasę i napisz dla niej regułę CSS.

Wskazówka do wariantu B

Przed obsługą zdarzenia utwórz let clickCount = 0;. Wewnątrz funkcji użyj clickCount = clickCount + 1;, a wynik połącz z tekstem.

Jak sprawdzić rozwiązanie?

Wariant A nie może psuć hierarchii nagłówków ani układu karty. Wariant B powinien po kolejnych kliknięciach wyświetlać kolejno 1, 2 i 3, bez błędów w konsoli.

Dla wariantu A obejrzyj nową sekcję w Elements i jej reguły w Styles. Dla wariantu B obserwuj zmieniany tekst w Elements oraz wartość licznika w Console. W obu wariantach wykonaj test przy wąskim oknie przeglądarki.

PUBLIKACJA

Udostępnij stronę przez GitHub Pages

Gotową stronę można opublikować bez tworzenia własnego pipeline’u i bez pliku GitHub Actions. GitHub Pages pobierze statyczne pliki bezpośrednio z gałęzi main i katalogu głównego repozytorium.

01

STRUKTURA REPOZYTORIUM

Umieść index.html w katalogu głównym

Plik wejściowy musi nazywać się dokładnie index.html. GitHub Pages odnajdzie go automatycznie pod głównym adresem witryny. Wszystkie ścieżki powinny być względne i zachowywać wielkość liter.

developer-card/
├── index.html       # strona otwierana jako pierwsza
├── about.html       # podstrona „O projekcie”
├── resources.html   # podstrona z odsyłaczami
├── styles.css       # wspólny arkusz stylów
└── script.js        # skrypt używany przez index.html

Przy takiej strukturze linki w dokumentach mają prostą postać:

<link rel="stylesheet" href="styles.css">
<a href="about.html">O projekcie</a>
<a href="resources.html">Materiały</a>
<script src="script.js"></script>
Nie używaj ścieżek z dysku

Odwołania takie jak C:\Users\... albo file:///... działają wyłącznie na Twoim komputerze. W repozytorium używaj nazw i ścieżek względnych. Serwer rozróżnia także About.html od about.html.

02

GIT + GITHUB

Wyślij projekt na gałąź main

Utwórz na GitHubie nowe repozytorium, np. developer-card. Nie dodawaj podczas tworzenia README, licencji ani .gitignore, jeżeli lokalny katalog zawiera już gotowy projekt. Następnie w terminalu, wewnątrz katalogu developer-card, wykonaj:

git init
git add .
git commit -m "feat: add developer card website"
git branch -M main
git remote add origin URL_REPOZYTORIUM
git push -u origin main

Zastąp URL_REPOZYTORIUM adresem HTTPS skopiowanym z GitHuba. Przed użyciem git add . uruchom git status i upewnij się, że dodajesz wyłącznie pięć plików projektu.

Bez własnego pipeline’u

Nie twórz katalogu .github/workflows, pliku deploy.yml ani konfiguracji npm. Dla tej statycznej strony wystarczy publikowanie bezpośrednio z brancha.

03

SETTINGS → PAGES

Wybierz main oraz /(root)

  1. Otwórz repozytorium na GitHubie i przejdź do Settings → Pages.
  2. W sekcji Build and deployment, przy opcji Source, wybierz Deploy from a branch.
  3. Jako branch wybierz main, a jako katalog /(root).
  4. Kliknij Save i poczekaj, aż GitHub pokaże adres opublikowanej strony.
  5. Otwórz adres w nowej karcie. Pierwsza publikacja może potrwać kilka minut.

Adres strony projektu ma zwykle postać:

https://NAZWA-UŻYTKOWNIKA.github.io/developer-card/
Repozytorium a dostępność strony

Na bezpłatnym koncie najprościej użyć repozytorium publicznego. Nie publikuj w nim haseł, tokenów, prywatnych adresów ani innych danych, których nie chcesz udostępnić w Internecie.

04

TEST PRODUKCYJNY

Sprawdź opublikowaną wersję

  1. Otwórz stronę w trybie prywatnym przeglądarki, bez logowania do GitHuba.
  2. Przejdź z index.html do obu podstron i wróć przez nawigację.
  3. Sprawdź wygląd strony i działanie przycisku JavaScript.
  4. Otwórz DevTools i upewnij się, że Console nie zawiera błędów, a pliki w Network nie zwracają statusu 404.
  5. Zmniejsz szerokość okna i sprawdź, czy karta mieści się na ekranie.
DevTools — sprawdź

W Network odśwież publiczny adres i sprawdź statusy dla index.html, styles.css i script.js. Po przejściu na podstrony znajdź również about.html i resources.html. Każdy zasób powinien zostać pobrany bez błędu 404.

    ✓
  • Publiczny adres automatycznie otwiera index.html.
  • CSS, JavaScript, nawigacja i odsyłacze działają również poza lokalnym komputerem.
  • Repozytorium nie zawiera własnego workflow publikacyjnego.
10

PODSUMOWANIE

Opowiedz, jak działa projekt

W parach wyjaśnijcie sobie projekt bez czytania kodu linia po linii. Jedna osoba odpowiada za HTML i CSS, druga za JavaScript, a następnie zamieniacie się rolami.

  • Potrafię wskazać treść widoczną w dokumencie i metadane w head.
  • Potrafię wyjaśnić różnicę między elementem, klasą i identyfikatorem.
  • Wiem, jak HTML dołącza pliki styles.css oraz script.js.
  • Rozumiem selektor, właściwość i wartość w regule CSS.
  • Potrafię odnaleźć element przez querySelector i obsłużyć zdarzenie click.
  • Potrafię znaleźć pierwszy błąd i numer linii w konsoli.
  • Projekt działa po ponownym otwarciu index.html.
EXIT TICKET

Napisz na kartce lub w wiadomości trzy zdania: „HTML odpowiada za…”, „CSS odpowiada za…”, „JavaScript odpowiada za…”. Dodaj jedno pytanie, które nadal masz po zajęciach.

11

DIAGNOSTYKA

Gdy rezultat różni się od ekranu

Po odświeżeniu nic się nie zmienia

Najpierw zapisz aktywny plik. Sprawdź, czy przeglądarka pokazuje index.html z właściwego katalogu. Wykonaj pełne odświeżenie i porównaj nazwę katalogu w pasku adresu.

HTML działa, ale nie ma stylów

Sprawdź nazwę styles.css, element link w head oraz zakładkę Network w DevTools. Błąd 404 oznacza zwykle złą ścieżkę.

Jedna reguła CSS nie działa

Sprawdź selektor, nawiasy klamrowe, dwukropek i średnik. W zakładce Elements zobacz, czy reguła jest widoczna i czy inna reguła jej nie zastępuje.

Przycisk nie reaguje

Otwórz Console i zacznij od pierwszego błędu. Porównaj id w HTML z selektorem w querySelector. Sprawdź również, czy script.js jest poprawnie dołączony.

W konsoli pojawia się null

JavaScript nie znalazł elementu pasującego do selektora. Sprawdź znak # dla identyfikatora, znak . dla klasy i dokładną pisownię nazwy.

Zmiany w DevTools zniknęły

DevTools pozwala eksperymentować na aktualnie wyświetlanej stronie. Aby zachować zmianę, przepisz ją do odpowiedniego pliku w wybranym IDE i zapisz.
