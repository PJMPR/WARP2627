01

CEL SPOTKANIA

Po laboratorium potrafisz

  • Samodzielnie utworzyć publiczne repozytorium na GitHubie.
  • Przygotować czytelny dokument w Markdownie i skorzystać z jego dokumentacji.
  • Podzielić pracę na 3–5 logicznych commitów na osobnej gałęzi.
  • Utworzyć, opisać i połączyć Pull Request z gałęzią main.
02

WAŻNE PRZED STARTEM

Repozytorium będzie publiczne

PRYWATNOŚĆ

Nie wpisuj prawdziwego numeru telefonu, adresu zamieszkania, numerów dokumentów ani innych wrażliwych danych. Możesz użyć przykładowego adresu e-mail albo pozostawić dane kontaktowe jako ogólny opis.

A / REPO

Nowy projekt

Załóż własne publiczne repozytorium przeznaczone wyłącznie do tego zadania. Nazwa powinna być czytelna, np. sciezka-w-informatyce.

B / PLIKI

Prosta struktura

Umieść opis swojej ścieżki w pliku sciezka.md, a w README.md krótko opisz, czego dotyczy repozytorium.

C / ŹRÓDŁA

Dokumentacja

Możesz korzystać z dokumentacji Markdowna. W README dodaj link do dokumentacji, z której korzystałeś.

03

ZADANIE GŁÓWNE

Opisz swoją ścieżkę

Stwórz dokument, który przedstawia Ciebie jako osobę rozpoczynającą lub rozwijającą swoją drogę w informatyce. Treść i styl pozostają Twoją decyzją.

Dokument powinien zawierać

  • imię lub nazwę prezentowaną w dokumencie oraz krótkie podsumowanie;
  • doświadczenie związane z informatyką, nawet jeśli pochodzi z nauki własnej;
  • cele związane ze studiami i plan rozwoju;
  • znane narzędzia, technologie albo obszary zainteresowań;
  • informację o projektach, kursach, kołach naukowych lub innych aktywnościach.

Spróbuj użyć

  • nagłówków różnych poziomów;
  • list punktowanych lub numerowanych;
  • wyróżnienia tekstu, linków i poziomego separatora;
  • tabeli umiejętności lub planu rozwoju;
  • odsyłacza do wybranego profilu albo dokumentacji.
PUNKT WYJŚCIA

Nie kopiuj gotowego szablonu. Zbuduj własną strukturę. Jeśli nie masz jeszcze doświadczenia zawodowego, opisz sposób nauki, ukończone ćwiczenia, zainteresowania techniczne i cele na najbliższy rok.

04

WORKFLOW GIT / GITHUB

Pokaż uporządkowaną pracę

Wykonaj pracę samodzielnie, dobierając poznane narzędzia i sposób działania. Instrukcja nie podaje konkretnych komend — ważne jest rozumienie kolejnych etapów.

  1. Utwórz nowe, publiczne repozytorium na swoim koncie GitHub.
  2. Przygotuj lokalną kopię repozytorium i rozpocznij pracę na osobnej gałęzi.
  3. Rozwijaj dokument w 3–5 logicznych etapach, np. struktura, opis doświadczenia, cele, formatowanie i poprawki.
  4. Przed utworzeniem PR sprawdź historię, zawartość plików i różnice względem main.
  5. Utwórz Pull Request z opisem wykonanej pracy. Połącz go z main dopiero po sprawdzeniu podglądu zmian.
  6. Na końcu sprawdź, czy repozytorium zawiera gotowy opis ścieżki, README i czytelny ślad pracy.
05

DOKUMENTACJA

Uzupełnij README

README nie jest kopią dokumentu. To krótka dokumentacja repozytorium, która pomaga innej osobie zrozumieć, co znajduje się w projekcie.

  • Dodaj tytuł repozytorium i jednozdaniowy opis.
  • Wskaż plik zawierający opis Twojej ścieżki.
  • Napisz, że dokument powstał w Markdownie.
  • Dodaj link do wykorzystanej dokumentacji Markdowna.
  • Możesz dodać krótką notatkę o tym, czego nauczyłeś się podczas zadania.
06

KRYTERIA UKOŃCZENIA

Sprawdź przed oddaniem

  • Repozytorium jest publiczne i znajduje się na Twoim koncie GitHub.
  • Pliki sciezka.md i README.md są czytelne i poprawnie wyświetlają się na GitHubie.
  • Dokument zawiera doświadczenie informatyczne, cele związane ze studiami i informacje o zainteresowaniach.
  • W dokumencie wykorzystano kilka elementów składni Markdowna.
  • Historia zawiera od 3 do 5 logicznych commitów wykonanych na osobnej gałęzi.
  • Pull Request został utworzony, opisany i połączony z main.
  • Link do repozytorium oraz link do Pull Requestu są gotowe do przekazania prowadzącemu.
DLA CHĘTNYCH

Dodaj sekcję „Projekty” z linkami do wcześniejszych prac albo przygotuj drugą wersję dokumentu, np. krótszą wersję profilową.

07

POMOC

Gdy coś nie działa

GitHub pokazuje surowy tekst zamiast formatowania

Sprawdź rozszerzenie pliku i składnię Markdowna. Podgląd pliku na GitHubie powinien pokazywać sformatowany dokument.

Nie wiem, jak podzielić pracę na commity

Potraktuj każdy commit jako osobny, zrozumiały etap: struktura dokumentu, treść, umiejętności, formatowanie albo poprawki.

Nie mam doświadczenia informatycznego

Opisz naukę własną, ćwiczenia, konfigurację środowiska, zainteresowania, udział w zajęciach i cele. Doświadczenie nie musi oznaczać zatrudnienia.

Nie chcę publikować prywatnych danych

To właściwa ostrożność. Użyj danych przykładowych, ogólnego kontaktu albo pomiń informacje, których nie chcesz udostępniać publicznie.
